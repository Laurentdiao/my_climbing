# 攀岩记录工具产品能力说明

**日期**: 2026-06-21
**状态**: accepted-for-mvp
**目标形态**: 手机优先的静态个人攀岩记录网站，部署在 GitHub Pages，数据用 Git 管理，不做视频托管。

## CAPABILITY

这个产品让一个攀岩者拥有自己的公开攀岩主页：用结构化数据记录每次室内攀岩训练的日期、岩馆、项目、难度、完成情况、线路数量、备注和外部视频链接；网站自动生成时间线、场次详情和个人统计。第一版不提供在线登录后台、不上传视频文件、不依赖数据库或服务器，所有公开数据由仓库里的 JSON 文件驱动。

## 用户和场景

主要用户是站点拥有者本人。拥有者通过修改仓库中的数据文件来更新记录，然后提交 Git 版本并由 GitHub Pages 自动发布。

公开访客不需要登录，只能浏览已经发布到静态站点中的记录、统计和外部视频链接。访客不能评论、点赞、关注、投稿或编辑。

核心场景是“把朋友圈/小红书之外的攀岩经历沉淀成自己的个人网站”。视频仍然发在小红书等平台，本系统记录链接、标题和备注。

## 固定约束

- 从零开始，没有既有代码。
- 自用优先，但需要公开分享。
- 手机优先，桌面辅助。
- 不租服务器。
- 不做 ICP 备案。
- 优先使用 GitHub Pages 这类静态托管。
- 第一版不托管视频文件，只记录小红书或其他外部视频链接。
- 第一版不需要登录、云数据库、在线表单提交或实时同步。
- 第一版不做社交关系、排行榜、关注、评论、公开线路数据库、地图或岩馆线路库。
- 第一版以室内抱石为主，但数据模型保留 `discipline` 字段以便扩展到难度攀岩。

## MVP 范围

MVP 必须包含：

- 静态个人主页：展示个人简介、核心统计和最近训练。
- 训练时间线：按日期展示场次。
- 场次详情：显示岩馆、日期、项目、线路记录、备注和外部视频链接。
- 岩馆标签：在数据文件中维护，可在界面中筛选。
- 线路记录：难度标签、难度排序值、项目类型、完成状态、尝试次数、线路数量。
- 批量记录：一条记录可代表多条同难度/同状态线路，字段 `quantity` 表示数量。
- 外部视频链接：每条线路可选记录 `videoUrl`、`videoPlatform`、`videoTitle`。
- 自动统计：总场次、总线路数、按岩馆分布、按难度分布、按月份趋势、完成率、最高完成难度。
- 数据校验脚本：检查 JSON 数据结构、必填字段、日期、数量、难度排序和链接格式。
- GitHub Pages 部署配置。

MVP 不包含：

- 视频上传、视频压缩、对象存储、CDN、转码。
- 登录后台和数据库。
- 在线多人编辑。
- 私密记录托管。发布到 GitHub Pages 的内容视为公开内容。
- 第三方平台 API 同步。
- 原生 iOS/Android App。
- 复杂训练计划或周期化训练。

## 关键产品规则

- 一个训练场次可以有多条线路记录。
- 一条线路记录可以代表 1 条实际线路，也可以代表多条同质线路，字段 `quantity` 表示数量。
- 外部视频链接可以绑定到任意线路记录；如果 `quantity > 1`，UI 应提示这是“相关视频”而不是逐条线路视频。
- 难度必须同时保存显示标签和排序值：显示标签用于 UI，排序值用于统计和趋势。
- 项目类型第一版至少支持 `bouldering` 和 `lead`，默认是 `bouldering`。
- 完成状态第一版至少支持 `flash`、`sent`、`repeat`、`attempted`、`project`。
- 统计中的线路数量必须使用 `quantity`，不能只按记录行数计算。
- 所有提交到公开数据文件的内容都视为公开发布，不要写入隐私信息。

## 数据所有权和信任边界

公开数据归站点拥有者维护，源数据位于 Git 仓库。Git 提供历史版本和回滚能力。

因为第一版没有后端和登录系统，所以不存在服务端权限控制。安全边界非常简单：发布到站点的数据就是公开数据；不想公开的内容不要提交到公开数据文件。

视频文件不进入仓库，也不进入网站托管服务。网站只保存外部链接，避免大文件、带宽、备案、存储费用和数据泄漏风险。

## 成功标准

- 拥有者可以通过编辑一个 JSON 文件新增训练记录。
- `npm run validate:data` 能在发布前发现明显数据错误。
- `npm run build` 能生成可部署到 GitHub Pages 的静态站点。
- 公开访客可以打开主页并看到时间线、统计和外部视频入口。
- 移动端浏览体验完整，文字不溢出，筛选和详情页好用。
- 代码结构允许未来替换为数据库或视频托管，但第一版不需要这些基础设施。

## 后续可选方向

- 增加本地编辑器页面：在浏览器里填写记录，然后导出 JSON，由拥有者提交到仓库。
- 增加视频托管：如果以后真的需要上传视频，再引入对象存储和本地/浏览器侧压缩。
- 增加私密数据：如果未来需要私密记录，必须引入认证和后端，不能继续用纯静态公开数据。
