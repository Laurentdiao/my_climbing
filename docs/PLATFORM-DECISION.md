# 平台决策说明

**日期**: 2026-06-21
**状态**: accepted-for-mvp

## 用户最新约束

- 最好不用备案。
- 不想租服务器。
- 能用 GitHub Pages 更好。
- 视频可能很多，占用空间大。
- 如果视频上传会复杂或昂贵，第一版可以不上传视频，只记录小红书等外部链接。

## 决策

MVP 使用 GitHub Pages 静态站点，不使用 Supabase、Vercel Server Functions、PocketBase、VPS 或对象存储。

视频不上传到本系统，只记录外部视频链接。

## 为什么不是 Supabase

Supabase 是一个后端即服务平台，提供数据库、登录、对象存储、实时能力和 Edge Functions。它也支持自托管，但自托管需要自己负责服务器、更新、安全、备份和可用性。

Supabase 不是“不可靠”，但它不适合当前 MVP：

- 它解决的是“有后端、有登录、有数据库、有存储”的问题，而当前 MVP 可以完全静态化。
- 免费额度可能够做小数据记录，但视频存储和流量很容易变成成本来源。
- 使用托管 Supabase 意味着数据放在第三方平台，权限配置错误会带来数据暴露风险。
- 中国内地访问境外 SaaS 没有强保证。
- 自托管 Supabase 又回到了“租服务器和运维”的问题。

## 为什么不是 GitHub Pages 托管视频

GitHub Pages 适合静态网页，不适合大量视频文件。

官方限制中包括：

- Pages 站点大小限制和仓库大小建议限制。
- Pages 有软带宽限制。
- 普通 Git 仓库对大文件有警告和硬限制。

因此不要把视频放进仓库，也不要把 GitHub Pages 当视频 CDN。

## 为什么接受外部视频链接

外部视频链接让 MVP 轻很多：

- 不需要存储费用。
- 不需要视频压缩管线。
- 不需要处理手机上传失败。
- 不需要对象存储权限。
- 不需要 CDN 或带宽预算。
- 小红书本来就是用户当前发布视频的地方，第一版只做“索引和整理”。

代价：

- 视频可用性依赖小红书等外部平台。
- 公开访客可能需要跳转打开。
- 如果外部链接失效，本系统只能显示失效链接，不能恢复视频。

## 备案和中国内地访问

使用 GitHub Pages 的 `github.io` 域名或境外托管通常不走中国大陆云服务备案流程。但这不是法律意见。

重要取舍是：不备案、不租大陆服务器，就不能保证中国内地访问稳定。GitHub Pages 是低成本、低运维的个人主页方案；如果未来必须追求中国内地强可用，通常需要大陆云服务/CDN，并完成备案。

## 安全模型

MVP 没有登录和私密数据。所有提交到 `src/data/climbing-log.json` 的内容都视为公开。

不要提交：

- 私密备注。
- 未公开的视频链接。
- 身份证、手机号、住址等敏感信息。
- 任何 API key 或 token。

## 未来升级条件

只有当以下需求真实出现时，才考虑引入后端：

- 需要手机上直接在线新增记录，不想通过 Git 更新。
- 需要私密记录。
- 需要多人协作。
- 需要本系统托管视频。
- 需要自动从第三方平台同步。

到那时再重新比较：

- GitHub Pages + GitHub API
- Cloudflare Pages + D1/R2
- Supabase
- PocketBase
- 国内云开发/对象存储
